# Market Alert Watchlist and Retrospective

- The alerts page reads cached `briefs` from its existing authenticated snapshot/SSE endpoint. Reads and scope selection never invoke AI.
- The existing opportunity worker checks independently every ten minutes. A shared SQLite atomic claim persists the deadline across restarts and overlapping workers. A serialized, one-time schema migration resets the old three-hour deadline; legacy 3h count summaries cannot appear as current tracking.
- The default internal `3h` scope scans the complete three-hour alert window and selects at most three symbols, using existing opportunity enrichment. The latest alert must be within an hour, both observation and fetch timestamps within twenty minutes, and required price/volume data present. Missing, stale, reversed or cooled signals may leave the list empty. Historical alert count is only a tie-breaker.
- Each candidate has a rule-derived state, two numeric evidence lines, a next observation and removal conditions. Stable confirmation is distinguished from strengthening. Previous candidates that disappear or weaken are listed under this cycle's downgrades. The 24h retrospective keeps frequency aggregation and at most five symbols.
- Small measurement changes refresh deterministic evidence without regenerating narration. Current-list AI sees only qualitative facts included in its material fingerprint. Retrospective AI sees only fingerprinted aggregate fields, with an independent three-hour generation ceiling. Changed, nonempty scopes share one bounded request; a failed request waits for the next ten-minute check and never switches providers automatically.
- M3 uses thinking disabled and a 2,200-token completion limit for this feature only. Existing homepage, opportunity explanations and WeCom behavior are unchanged.
- Model output may only explain the selected symbols. Concrete numbers come from cached data and rules. OI changes do not establish a trader's identity or net inflows. Squeeze candidates use independent short-period candle metrics because some longer-period enrichment fields retain trigger-time values.
- Scope and symbol validation remains strict. A narrowly recognized missing opening quote on a known JSON key can be recovered; unsafe numeric or overlong prose falls back per field to deterministic wording. No price, symbol or evidence is invented to repair a response.
- An AI failure saves the current rule result, including removals, instead of restoring obsolete candidates. AI availability and data freshness are separate. The browser uses its existing parent clock to flag an old check, observation or trigger even without a new server response. No additional Binance, Signal or browser polling request is introduced.
- Storage: `market_alert_brief` in the existing market-alert SQLite database. No extra service, credential, port or public API is introduced.

Tests cover full-window counts, qualification and ranking, state transitions, stale/future/missing inputs, squeeze provenance, migration, persisted claims, late-response protection, AI reuse and failure, malformed/numeric output, and component freshness. The opt-in `e2e/market-watchlist.spec.ts` uses an isolated `MARKET_ALERTS_DB` and `SIGNAL_HUB_RUNTIME_DIR` with `SIGNAL_E2E_MARKET_WATCHLIST=1` to verify authenticated rendering, real SSE updates, scope retention, and desktop/mobile layout.
