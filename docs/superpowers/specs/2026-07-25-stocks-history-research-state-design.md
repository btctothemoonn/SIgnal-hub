# Stocks 历史日线回填与研究状态管理设计

## 目标

在不改动 Signal Flow 和现有 Stocks 信息架构的前提下，完成两个独立但协同的能力：

1. 为 Stocks 研究池中的股票补齐从 `2026-05-06` 开始的历史日线，并持续自动修复缺口。
2. 为每只股票提供可跨设备同步、不会被部署覆盖的研究状态管理。

## 范围

本轮包含：

- 已有研究池股票的历史日线一次性回填。
- 后续新增股票自动回填至统一起点 `2026-05-06`。
- 后台每日检查历史数据缺口并增量补齐。
- 个股研究状态的持久化、读取和修改。
- Stocks 页面按研究状态筛选。
- 个股详情首屏展示和编辑研究状态。

本轮不包含：

- Signal Flow 的任何功能或界面调整。
- 自动交易或券商下单。
- 完整 SEPA、期权 IV/GEX 或新的付费行情源。
- AI 自动修改人工研究状态。

## 总体架构

历史行情和研究状态分别使用独立的逻辑模块，但都持久化在 VPS 本地 SQLite 中。历史行情继续复用现有 Stocks performance 数据库和读取接口，避免创建第二套曲线数据。研究状态使用独立数据库，避免与行情缓存生命周期耦合。

浏览器只通过 API 读写研究状态。手机、笔记本和电脑访问同一 VPS，因此看到同一份状态。数据库文件位于 `.signal-hub` 持久化目录，代码部署和构建不会覆盖。

## 历史日线回填

### 数据范围

- 所有研究池股票统一从 `2026-05-06` 开始。
- 结束时间为最近一个可获得的交易日。
- 后续新增股票也回填到 `2026-05-06`，而不是从加入研究池当天开始。
- 每个交易日保存一个收盘价数据点。

### 数据源顺序

1. Yahoo Finance 日线接口作为默认来源，不新增密钥成本。
2. Yahoo 请求失败、返回空数据或缺少明显区间时，使用已配置的 EODHD 作为备用。
3. 单只股票两个来源都失败时，保留已有数据并记录失败，不清空曲线。

### 写入策略

- 复用现有 Stocks performance SQLite。
- 以 `ticker + trading_date` 作为幂等键执行 upsert。
- 已存在且有效的数据默认不重复请求。
- 回填任务先计算数据库缺失区间，再按区间请求，不每天重拉完整历史。
- 数据点记录来源和抓取时间，便于判断新鲜度和排查错误。

### 执行方式

- 提供一次性回填脚本，供本地和 VPS 手动执行。
- Stocks cache worker 每天运行一次缺口检查。
- 新增研究池股票后，下一次 worker 周期自动发现并补齐。
- 页面请求不直接触发整段历史回填，避免用户打开 Stocks 时阻塞。

### 曲线兼容

- `/api/stocks-performance` 的现有返回结构保持兼容。
- 起点仍由 `startDate=2026-05-06` 控制。
- 曲线继续支持 `maxPoints` 降采样，同时保留首尾点。
- 某只股票回填失败时，其他股票仍正常返回。

## 股票研究状态

### 状态字段

每只股票保存：

- `status`: `watch`、`waiting`、`holding`、`avoid`
- `conviction`: 1 至 5，允许为空
- `entryZone`: 计划买入区，允许为空
- `invalidation`: 失效条件，允许为空
- `nextCatalyst`: 下个催化或待跟踪事件，允许为空
- `thesis`: 研究逻辑备注，允许为空
- `updatedAt`: 最后更新时间

界面中文标签分别为：

- `watch`: 观察
- `waiting`: 等待
- `holding`: 持有
- `avoid`: 回避

未保存过状态的股票默认为 `watch`，但不会仅因读取而写入数据库。

### 持久化

- 使用独立 SQLite 文件 `.signal-hub/stocks-research.sqlite`。
- `ticker` 是唯一键，统一转成大写。
- 更新使用 upsert，避免重复记录。
- 数据库文件不纳入 Git。
- 研究状态不会被行情缓存清理任务删除。

### API

新增 Stocks 专用接口：

- `GET /api/stocks-research-state`
  - 返回全部研究池股票的状态映射。
- `GET /api/stocks-research-state?ticker=NVDA`
  - 返回单只股票状态。
- `PUT /api/stocks-research-state`
  - 接收单只股票的完整研究状态并执行 upsert。

接口要求：

- 复用网站现有登录保护，不新增独立登录系统。
- 拒绝不在研究池中的 ticker。
- 校验状态枚举、信心等级和文本长度。
- 返回稳定的 JSON 错误结构，写入失败不影响其他 Stocks API。

## 页面设计

### 个股详情

在 Stocks 个股详情首屏增加紧凑的“研究状态”区域：

- 状态使用分段选择控件。
- 信心等级使用 1 至 5 的步进或选择控件。
- 买入区、失效条件、下个催化和研究逻辑使用紧凑输入区域。
- 明确显示最后更新时间和保存状态。
- 保存失败时保留用户尚未提交成功的输入，并显示错误。

该区域不替代现有行情、财务、催化、风险和新闻内容。

### 股票池筛选

Stocks 股票池增加研究状态筛选：

- 全部
- 观察
- 等待
- 持有
- 回避

筛选只影响当前股票池显示，不改变分类顺序和股票数据。

### 手机端

- 状态控件允许换行但不使用横向大表格。
- 输入项使用单列布局。
- 保存按钮保持可点击区域充足。
- 不增加新的底部导航项。

## 错误处理与可观测性

历史回填：

- 记录每个 ticker 的成功数量、缺失区间、数据源和错误原因。
- 单只股票失败不终止整批任务。
- worker 输出本轮成功、跳过和失败统计。
- API 在有旧数据时继续返回旧数据，并标记新鲜度。

研究状态：

- 数据库初始化失败时，详情页显示“研究状态暂不可用”，其他内容继续加载。
- 非法输入返回 `400`。
- 未登录请求沿用现有权限处理。
- 数据库写入异常返回 `500`，不伪装为保存成功。

## 测试

### 历史回填

- 缺少完整历史时能从 `2026-05-06` 生成请求区间。
- 已有部分数据时只补缺口。
- 相同日期重复回填执行 upsert，不产生重复点。
- Yahoo 失败时切换 EODHD。
- 单只股票失败不影响其他股票。
- 新增股票能被下一次缺口检查发现。

### 研究状态

- 默认状态为 `watch`。
- ticker 统一大写并唯一保存。
- 四种状态均可持久化。
- conviction 只接受 1 至 5 或空值。
- 非研究池 ticker 被拒绝。
- API 能读取、更新并返回一致数据。

### 页面

- 个股详情能显示默认状态和已有状态。
- 保存成功后更新时间更新。
- 保存失败时输入不丢失。
- 状态筛选能正确过滤股票。
- 缺失研究状态服务时，Stocks 其他模块仍正常显示。

### 完整验证

- 相关 Node 测试通过。
- `npm run lint` 通过。
- `npm run build` 通过。
- VPS 一次性回填后，研究池曲线均从可用的首个交易日起展示。
- VPS 服务重启后，研究状态仍存在且跨设备一致。

## 部署

1. 推送代码到 GitHub。
2. VPS 拉取相同提交并构建。
3. 首次运行历史回填脚本。
4. 重启 Stocks cache worker 和 web 服务。
5. 检查回填统计、API 返回和页面状态保存。
6. 确认 SQLite 文件位于持久化目录且未被 Git 跟踪。

## 验收标准

- 研究池现有和后续新增股票都能从 `2026-05-06` 起获得可用历史曲线。
- 数据源短暂失败不会删除已有曲线，也不会拖垮整个 Stocks 页面。
- 研究状态在手机、笔记本和电脑之间一致。
- 部署和服务重启不会丢失研究状态。
- Stocks 可以按研究状态筛选，个股详情可以编辑全部约定字段。
- Signal Flow 行为和界面没有变化。
