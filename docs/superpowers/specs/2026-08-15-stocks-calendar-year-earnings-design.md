# STOCKS 自然年财报列表与公开网页兜底设计

## 目标

把个股详情中的单季度“财报速览”改为按财报发布日期自然年组织的财报列表。2026 年只展示在 2026 年发布的财报；进入 2027 年后自动移除 2026 年记录，只展示 2027 年发布的财报。

系统应优先展示与当前投资决策最相关的季度，并在 API 覆盖不足时从公司官方 IR、SEC/官方财报和公开财经页面补齐发布日期、公司指引、分析师共识及公布值。所有值必须保留来源和口径，不允许把公司指引冒充分析师共识，也不允许伪造缺失数据。

## 展示规则

### 自然年范围

- 以财报 `reportDate` 所在的自然年分组，不使用公司财年作为页面过滤条件。
- 页面默认只展示当前自然年发布或计划发布的财报，最多四条。
- 当前自然年变化时，旧自然年的记录自动退出默认列表，不需要人工清理缓存。
- 卡片仍显示公司财年和季度，例如 `FY2027 Q2`，避免把自然年误认为公司财年。

### 即将发布的财报

- 当距离官方或可信来源确认的发布日期不超过 15 天时，将该季度插入列表顶部并默认展开。
- 距离发布日期超过 15 天时，不提前展示该季度。
- 即将发布的季度只展示已有的分析师共识、公司指引、发布日期和报告时段；公布值显示“等待公布”。
- 财报发布后，该季度自动转为已公布状态并补入实际值、同比和较预期。

### 已公布财报

- 其余记录按 `reportDate` 从新到旧排列。
- 每条均展示营收和净利润两行，以及预计值、公布值、较预期三列。
- 当前自然年不足四条时只展示已有记录，不用上一自然年的记录填满。

## 数据模型

在现有 `StocksFinancialSnapshot` 中增加独立的自然年展示列表，例如 `calendarYearEarnings`，每项继续使用 `StocksEarningsComparison`，并扩展以下状态：

- `reportDate`: 财报发布日期。
- `reportDateSource`: 日期来源与可信级别。
- `status`: `upcoming` 或 `reported`。
- `companyGuidance`: 公司官方营收指引，和分析师共识分开存储。
- `revenue.estimate` / `netIncome.estimate`: 分析师共识预计值。
- `revenue.actual` / `netIncome.actual`: 公布值。
- 每个字段继续保留 provider、direct/derived、币种、单位、scale、metric semantics 和 accounting basis。

`latestEarnings` 保留兼容，但 UI 改为消费 `calendarYearEarnings`，避免继续把最近已公布季度误当作当前关注季度。

## 数据完整性硬约束

- 已公布季度只有在营收预期、营收实际、净利润预期和净利润实际四项均有值时，才标记为 `complete`。
- 即将公布季度必须至少有营收预期和净利润预期；实际值在发布前固定显示“等待公布”，这不属于数据缺失。
- 净利润预期可以使用明确的净利润共识，也可以在 EPS 共识、币种、每股单位和稀释股数均可靠时使用 `EPS × diluted shares` 推导，并醒目标记“推导”。
- 净利润实际优先使用官方净利润；只有直接值无法取得且实际 EPS 与稀释股数口径明确时，才允许推导，并标记“推导”。
- 任何已公布季度缺少上述必要值时，数据状态标记为 `incomplete`，后台继续尝试下一来源并记录数据健康告警。UI 不得把该状态描述成正常完成，也不得以 `n/a`、空白或虚构数字掩盖。
- 默认列表的验收目标是当前自然年最多四个完整季度；若仍存在 incomplete 项，页面必须明确指出缺失字段和已尝试来源。

## 来源优先级

### 发布日期

1. 公司官方 IR 的活动或公告页面。
2. 公司官方新闻稿。
3. SEC 8-K/6-K 或正式财报文件中的发布日期。
4. Finnhub、EODHD、Alpha Vantage 等现有日历数据。
5. 公开财经页面。

只有可归属于同一 ticker、公司财年和季度的日期才允许合并。多个来源冲突时保留高优先级来源并记录诊断。

### 公布值

1. 公司官方财报或 IR 新闻稿。
2. SEC 正式文件。
3. Alpha Vantage、FMP、Yahoo 等现有结构化来源。
4. 公开财经页面。

### 分析师共识

1. FMP、Finnhub、EODHD、Alpha Vantage 的现有共识字段。
2. 可公开访问且无需登录的财经页面，例如能够明确给出季度、EPS 共识和营收共识的页面。
3. EPS 共识可在币种、每股口径和稀释股数均明确时推导净利润共识，并标记为 `derived`。
4. 对已公布季度，公开页面 provider 必须支持历史“estimate vs actual”记录，不能只读取当前季度共识。

### 公司指引

- 只从公司官方 IR、官方新闻稿或 SEC 正式文件提取。
- 公司指引单独展示为“公司指引”，不得写入“分析师共识”字段。
- 如果只有公司指引而没有共识，预计值区域展示指引并明确标签，不计算“较预期”。

## 公开网页采集层

新增独立 provider 层，不把网页解析混入 UI：

- `official-ir`: 抓取官方财报活动、新闻稿和指引。
- `sec-filings`: 读取 SEC 公司提交和正式财报文件。
- `public-consensus-page`: 从允许公开访问的财经页面解析季度营收/EPS 共识。

每个 provider 必须：

- 设置固定超时、User-Agent、每 ticker 请求上限和 12 小时缓存。
- 只解析明确的结构化 JSON、JSON-LD、表格或稳定文本标签，不从任意文章自由猜测数字。
- 保存页面 URL、抓取时间和解析口径。
- 页面结构变化时返回失败诊断，不把旧字段错配为新季度。
- 单个 provider 失败不阻断其他来源和页面渲染。

## 财期匹配

- 优先使用来源明确提供的公司财年和季度。
- 其次使用财期结束日，允许最多 7 天日期容差。
- 即将发布季度可根据上一个已公布季度推进一个季度，但必须由官方发布日期或可信财报日历确认，不能只根据当前日期创建空季度。
- 明确的财年、季度或 ticker 冲突必须拒绝合并。

## UI

- 个股详情中的“财报速览”改为自然年财报列表。
- 标题显示自然年，例如 `2026 财报`。
- 即将发布季度位于顶部，带“15 天内发布”状态和发布日期。
- 每个季度卡片显示 `FY年 + Q季度`、报告日期、盘前/盘后状态。
- 每个季度保留营收/净利润及预计值、公布值、较预期。
- 分析师共识、公司指引、公布值的来源分别可见；推导值必须显示“推导”。
- 手机端采用纵向季度卡片，四列内部使用紧凑网格和换行，不隐藏字段、不产生横向滚动。
- 当年无任何记录时显示“当年暂无已确认财报”，而不是回退显示上一年。
- 已公布季度的预期值和实际值均为必显字段；即将公布季度的实际值显示“等待公布”。

## 缓存与刷新

- 后台财务预热时同时更新当前自然年的财报列表。
- 官方日期和公司指引缓存 12 小时；财报发布前 15 天可缩短为 2 小时。
- 财报发布日及次日，公布值缓存刷新周期缩短，取得正式结果后恢复常规周期。
- 旧缓存读取时按当前自然年重新过滤，不需要删除历史文件。

## 测试

- 当前自然年只返回当年财报，跨年后不返回上一年。
- NVDA 在 2026 年 8 月 15 日显示 `FY2027 Q2` 为顶部 upcoming 项，而不是只显示 `FY2027 Q1`。
- NVDA `FY2027 Q2` 在发布前必须显示营收预期和净利润预期，实际值显示“等待公布”。
- NVDA 当前自然年内已公布季度必须同时展示预期值和实际值，不得只展示 Alpha Vantage 实际值。
- 距离发布日期超过 15 天时 upcoming 项不展示，等于 15 天时展示。
- 财报公布后 upcoming 自动转为 reported，并计算可比口径下的较预期。
- 官方 IR 日期优先于 API 和公开财经页面。
- 公司指引与分析师共识保持独立。
- API 全部失败时，公开网页仍能补充可验证字段。
- 已公布季度缺任一必需预期值或实际值时测试失败，不能把 incomplete 当作完成。
- 网页结构变化、超时或 4xx/5xx 不影响其他季度和其他 STOCKS 功能。
- 手机端四季度列表字段完整且无横向溢出。
- Signal Flow、Holding、抖音和 Signal 首页海力士溢价功能保持不变。

## 非目标

- 不抓取需要登录或付费墙后的内容。
- 不用搜索摘要或 AI 自由生成财务数字。
- 不把公司指引和分析师共识合并为一个数字。
- 不删除历史缓存，只改变默认展示范围。
