# 方程式新闻交易页（/news）设计与实施方案

日期：2026-11-16
状态：原始设计。当前实现、接口与启用方式见实施记录和交易服务运维文档。
参考：NewsLiquid 交易页（https://app.newsliquid.com/trade，需登录；布局依据其公开文档 docs.newsliquid.com 的 News trading / Interface / Event Panels 三页）
数据源：方程式新闻 https://eqn.news/（免费、无需 Key，内容为自动抓取和机器翻译，不构成投资建议）

## 1. 目标与范围

在 Signal Hub 新增独立页面「新闻交易」，路径 `/news`，导航与「信号 / 异动 / AI+币圈情报站」并列。用途是秒级看到交易所公告、上币、大事件，点开就能看到对应币种的 K 线、新闻发布后的价格反应，以及 Signal 内部同币种的异动和 KOL 信号，并直接用币安子账户或 Hyperliquid API 钱包实盘下单。

本期包含：

- 方程式新闻实时流、频道和币种筛选、搜索。
- 新闻与币种行情联动：K 线、新闻时间点标记、发布后 1m/5m/15m/1h 涨跌。
- 与 Signal 现有异动板块、X/TG 信号按币种关联。
- 实盘交易：币安 U 本位合约（子账户 API）和 Hyperliquid 永续（API 钱包），新闻卡片快捷开仓、交易面板、持仓/挂单/成交、紧急全平。
- 重要新闻的 Web Push（复用现有推送通道和 VAPID）。

本期不包含：

- 现货、杠杆借贷、期权、TWAP、策略自动下单。所有订单都由用户手动点击发起。
- 资金划转和提现。API 权限本身就不开放这两项。
- AI Agent 侧栏。新闻本身已带中英翻译，默认不调用 AI。
- 自建新闻评分模型。本期只用规则打分，见第 5 节。

## 3. 页面设计

### 3.1 桌面布局（>=1280px）

```text
+--------------------------------------------------------------------------------------+
| Signal Hub 导航（现有 app-shell）                                                    |
+--------------------------------------------------------------------------------------+
| [全部|主站|币安|韩国|上币Alpha|TradFi|异动|OI] [搜索 /] [来源 v] [*] [铃] [账户 币安 v]|
+---------------------------+-----------------------------------+----------------------+
| 新闻流 (约 420px)          | K 线区 (自适应)                     | [交易|详情] (约 340px)|
|  有 3 条新消息，点击查看   |  XXXUSDT 永续  $0.43  +8.4%  币安   |  可用 1,820 USDT     |
| +-----------------------+ |  [1m 5m 15m 1h 4h 1d]  [新闻标记 v] |  [市价|限价]         |
| |# 币安将上线 XXX 永续   | |                                   |  金额 [ 500 ] USDT   |
| |  币安公告 · 05:18:45  | |  K 线 + 新闻竖线 + 自己的买卖点 B/S  |  [100][300][500][1k] |
| |  [上币] 分数 85       | |                                   |  杠杆 [3x v] 逐仓    |
| |  XXX +8.4% [多500][空500]|                                  |  止损 [-3%] 止盈 [  ]|
| |  要点: ...            | |                                   |  [ 开多 ]  [ 开空 ]  |
| +-----------------------+ +-----------------------------------+  当前持仓 XXX 多     |
| | 新闻卡片 ...          | | [持仓 2|挂单 1|成交|日志]            |  +12.4 USDT [平仓]   |
| |                       | |  XXX 多 500U 3x 入场 0.41 +12.4 [平]|                      |
| +-----------------------+ |  ...                    [全部平仓] |                      |
+---------------------------+-----------------------------------+----------------------+
| 新闻 正常 1.2s · 币安 已连接 · HL 已连接 · 今日已用 1,200/3,000U   数据来自方程式新闻 |

```

视觉沿用 Signal 现有深色终端风格，信息密度高，卡片圆角不超过 8px。重要程度用卡片左边框颜色区分，不用大块底色：

- 橙色：上币、下架、重大公告（规则分 >=80）。
- 绿色/红色：发布后 5 分钟涨跌超过 ±3% 的新闻（价格反应已知时）。
- 无边框：普通新闻。

### 3.2 新闻卡片

从上到下依次是：

1. 标题：默认中文（`i18n.zh`），原文语言不同时右上角提供「原文」切换。原文本身就是中文时不显示切换。
2. 来源行：来源图标 + `source.display_zh`、频道标签、秒级时间（北京时间 `HH:mm:ss`，超过今天显示 `MM-DD HH:mm:ss`）、规则分徽标、分享/复制链接图标。
3. 关联币种行：每个币一行，显示币种、当前价格、发布至今涨跌、发布时市值（`mc_at_publish`）、交易所标识、快捷开多/开空按钮、外链箭头。币种超过 3 个时折叠为「+N」。快捷按钮规则见 3.5 节；当前账户没有该币交易对时按钮置灰，悬停提示「币安/HL 无此合约」。
4. 公告要点：`data.announcement_digest.points` 有值时显示，最多 3 条，可展开。
5. 图片：`images` 有值时显示缩略图，点开大图。

点击卡片：选中该新闻，K 线切到第一个关联币种，并滚动到新闻时间点。点击币种行：只切换币种。

### 3.3 K 线区

- 数据复用现有 `src/app/api/market-alerts/charts/[symbol]` 的币安 K 线路由和缓存，周期只提供 1m、5m、15m、1h、4h、1d。1m 只拉最近 1 天，避免重复出现之前海力士 K 线的限流问题。
- 新闻标记：在 K 线对应时间画竖线和来源小图标，只标当前币种、规则分 >=70 的新闻；同一根 K 线多条新闻合并为数字角标，悬停显示卡片，可翻页。
- 选中新闻时，在图上标出发布价横线，并高亮发布后 1h 区间。
- K 线下方显示该币最近 20 条相关新闻的时间轴，点击可跳转。
- 没有币安合约或现货交易对的币种（例如部分 TradFi、韩国小币），K 线区显示「暂无币安行情」和原文链接，不报错。

### 3.4 右侧侧栏：交易标签

- 顶部账户选择：币安子账户 / Hyperliquid，显示可用保证金和连接状态。切换账户后交易对重新映射（例如币安 `1000PEPEUSDT` 对 HL `kPEPE`）。
- 下单：市价/限价分段控件，金额（USDT 名义价值）输入框和预设金额按钮，杠杆选择（默认 3x，上限由风控配置决定），逐仓/全仓（默认逐仓），可选止损和止盈百分比。
- 开多、开空两个大按钮，颜色跟随现有涨跌配色。点击后按钮进入「提交中」状态，防止重复点击。
- 下方显示当前币种的持仓、未实现盈亏、强平价和「平仓」「平一半」按钮。
- 下单回执以轻提示显示：成交均价、数量、手续费；失败时显示交易所原始错误码和中文说明。

### 3.5 快捷下单规则

- 新闻卡片上的快捷按钮是「开多 xxx」「开空 xxx」，金额取设置里的快捷金额（默认 200 USDT，可设 1-2 档），杠杆、逐仓和默认止损取交易面板的默认值。
- 确认方式在设置里选择：「点击即下单」或「二次确认」（默认二次确认）。二次确认是在按钮原位变成「确认开多 500U」，2 秒内再点一次才提交，不弹窗。
- 键盘快捷键默认关闭；开启后，选中新闻时 `B` 开多、`S` 开空，同样遵守确认方式。
- 所有快捷单都走服务端风控（第 7 节），前端金额只是请求参数，不是授权依据。

### 3.6 订单与持仓区（K 线下方）

- 标签：持仓、挂单、成交（最近 100 条）、下单日志。
- 持仓行：账户、币种、方向、名义价值、杠杆、入场价、标记价、未实现盈亏、强平价、止损止盈、平仓按钮。
- 挂单行：撤单按钮；顶部「撤销全部挂单」。
- 区域右上角「全部平仓」：撤销所有挂单并以 reduceOnly 市价平掉两个账户的全部持仓，需输入确认（长按 1.5 秒）。
- 下单日志显示每次请求：时间、关联新闻、账户、参数、风控结果、交易所响应、耗时。
- 成交在 K 线上显示 B/S 标记，悬停显示数量和均价。

### 3.7 币种详情标签

- 价格反应：发布价，以及发布后 1m / 5m / 15m / 1h 的涨跌幅和最大涨幅、最大跌幅。时间未到的格子显示「进行中」。
- 基础数据：价格、24h 涨跌、市值、FDV、流通市值、24h 成交额、资金费率、OI。优先使用现有异动板块已有的市值/FDV 数据，缺失时用 eqn `/api/v1/market` 的 `mc` 字段补充（该接口非官方，见风险一节）。
- Signal 关联：同币种最近 24h 的异动预警（暴涨暴跌、轧空）条数和最新一条；X/TG 信号中提到该币的条目，点击跳回对应页面。
- 外链：币安合约、币安现货、新闻原文、方程式 Telegram 帖子（`deliveries`）。

### 3.8 顶部工具栏

- 频道分段控件：全部、主站、币安、韩国、Alpha、TradFi、异动、OI。对应 eqn 频道 `all, main, binance, korea, alpha, tradfi, pricechange, oi`，其余频道（major、tier2、tier3、cz、earn）放进「更多」菜单。
- 搜索：输入币种代码时直接过滤币种，其他文字按标题搜索；`/` 聚焦；30 天以外的关键词搜索不支持，提示用户。
- 来源筛选：多选菜单，按 `source.group` 分组。
- 齿轮菜单：密度（紧凑/标准）、字号、只看带币种、合并重复新闻、显示原文。
- 铃铛：新闻提醒开关，打开后进入提醒规则设置（第四期，见 6.4 节）。
- 声音开关：新上币新闻到达时播放提示音，默认关闭。

### 3.9 手机布局（<768px）

- 首屏只有新闻流，频道控件横向滚动，搜索收进图标。
- 点击卡片弹出底部抽屉，依次显示 K 线（固定高度 260px）、交易面板、价格反应、Signal 关联、外链。
- 手机端快捷按钮强制二次确认，不受设置影响。
- 底部固定一个持仓入口，显示持仓数量和总未实现盈亏，点开是持仓列表和「全部平仓」。
- 底部状态栏缩成一个连接状态圆点，点开看详情。

### 3.10 状态

- 首次加载：骨架屏，先显示数据库里最近 100 条，再接实时流。
- 实时连接断开：状态栏变黄，显示「重连中」，期间后台补漏，不清空列表。
- eqn 限流（429）：状态栏显示「数据源限流，xx 秒后恢复」，前端不重试，由后端按 Retry-After 处理。
- 空结果：显示当前筛选条件和「清除筛选」按钮。
- 交易账户未配置：交易标签显示「未连接」，快捷按钮隐藏，新闻功能不受影响。
- 交易所断连或下单服务异常：交易按钮置灰并显示原因，持仓区显示最后一次同步时间。
- 风控拦截：按钮下方显示拦截原因，例如「超过单笔上限 500U」「今日亏损已达上限」。

## 4. 数据源与接入

### 4.1 eqn 接口优先级

| 用途 | 接口 | 是否官方文档 | 说明 |
| --- | --- | --- | --- |
| 实时推送 | `wss://api.eqn.news/public/ws` | 是 | 只覆盖 main 频道，无回放；30 秒发 `ping`；字段 `source_name, news_title, coins_included, url, timestamp(秒)` |
| 补漏和其他频道 | MCP `https://api.eqn.news/public/mcp` 的 `list_news(channel, coin, query, limit<=50, before)` | 是 | 返回 `next_cursor`，关键词搜索覆盖 30 天 |
| 详情 | MCP `get_news(no)` | 是 | 全语言正文、图片、Telegram 链接、结构化数据 |
| 降级 | RSS `https://api.eqn.news/public/rss?ch=&lang=zh` | 是 | 最新 50 条，缓存 60 秒，支持 ETag |
| 富字段列表 | `GET https://eqn.news/api/v1/news?limit=100&ch=` | 否 | 字段最全（`coins.mc_at_publish`、`announcement_digest`、`kind`），但可能随时变 |
| 市值补充 | `GET https://eqn.news/api/v1/market` | 否 | 压缩格式 `k` + `rows`，只做补充 |

原则：生产链路只依赖官方接口能跑通；`/api/v1` 作为字段增强，失败时自动降级，不影响新闻流。

### 4.2 限流预算（按 VPS 单 IP）

eqn 限制：全部接口合计 10 秒 120 次，超限暂停 10 秒；MCP 每秒 5 次、突发 30；WS 最多 20 连接、每秒新建 2 个；RSS 每秒 10 次。

本方案预算：

- WS：只开 1 个连接。
- 频道轮询：除 main 外的频道，每个频道每 15 秒调用一次 `list_news(limit=50)`。12 个频道约每秒 0.8 次。
- 详情：新新闻到达后补拉一次 `get_news`，全局每秒最多 2 次，排队处理。
- `/api/v1/news` 增强：每 30 秒一次，失败连续 5 次后暂停 10 分钟。
- 合计稳定在 10 秒 30 次以内，留出 75% 余量。
- 收到 429 时全局暂停，时长按 Retry-After，没有则 15 秒。

浏览器永远不直接请求 eqn，所有数据走 Signal 自己的接口。

## 5. 规则评分（替代 NewsLiquid 的 AI 评分）

分数 0-100，只用于排序、高亮、K 线标记和推送门槛，不代表多空判断：

| 条件 | 加分 |
| --- | --- |
| `kind=listing` 或标题含上线/上币/Listing/Delist/下架 | +50 |
| 来源为币安、Upbit、Bithumb、Coinbase、OKX 官方公告 | +25 |
| 频道 cz、major | +15 |
| 有关联币种 | +10 |
| 关联币发布时市值 < 5 亿美元 | +10 |
| 同一事件 10 分钟内已有更早报道（重复） | -40 |
| 无关联币种且频道为 tradfi | -10 |

规则写成纯函数并配单元测试，权重放在配置里，后续按回测结果调整。

## 6. 后端架构

```text
eqn WS(main) ----+
eqn MCP 轮询 ----+--> eqn-news worker (VPS, systemd) --> SQLite: .signal-hub/eqn-news/news.sqlite
eqn /api/v1 增强 -+          |                               |
                            +-- 价格反应计算(币安 K 线) -----+
                            +-- Web Push(规则命中)
Next.js: /api/eqn-news, /api/eqn-news/stream(SSE), /api/eqn-news/[no] --> /news 页面

浏览器 --(登录 + 交易解锁)--> Next.js /api/trade/* --(127.0.0.1 + 内部令牌)--> signal-hub-trader --> 币安 / Hyperliquid
                                                               |
                                                               +-- SQLite: .signal-hub/trader/trades.sqlite
```

### 6.1 Worker

- 新 systemd 服务 `signal-hub-eqn-news.service`，与 monitor985、x-owned-reader 独立，崩溃不影响其他采集。
- 开关 `EQN_NEWS_ENABLED`，默认关闭，上线时在 VPS 环境变量打开。
- WS 重连退避 1、2、4…30 秒；每次重连成功后用 `list_news(channel=main, before=最后一条)` 补齐断线期间的新闻。
- 去重键：eqn `no`；WS 帧没有 `no` 时用 `url + timestamp` 先入库占位，拉到详情后合并。
- 时间统一存毫秒 UTC，页面按北京时间显示。
- 数据保留 30 天，每天清理一次。

### 6.2 数据表

- `eqn_news`：`no` 主键、`id`、`published_ts`、`channels`(JSON)、`kind`、`source_slug`、`source_name_zh`、`title_zh`、`title_en`、`title_src`、`source_language`、`url`、`images`(JSON)、`digest`(JSON)、`deliveries`(JSON)、`score`、`dup_of`、`received_ts`、`origin`(ws/mcp/v1)。
- `eqn_news_coins`：`no`、`symbol`、`asset_id`、`mc_at_publish`、`binance_symbol`（映射后的交易对，可空）。
- `eqn_news_reaction`：`no`、`symbol`、`price_at_publish`、`chg_1m`、`chg_5m`、`chg_15m`、`chg_1h`、`max_up_1h`、`max_down_1h`、`completed_at`。发布后 1m、5m、15m、65m 各计算一次，用币安 1m K 线，复用 `market-alerts-store` 的 429 限流表。
- `eqn_worker_state`：最后游标、WS 状态、最近错误、限流暂停到期时间，给状态栏用。

### 6.3 网站接口

- `GET /api/eqn-news?channel=&coin=&q=&source=&before=&limit=`：默认 100 条，最大 200。
- `GET /api/eqn-news/[no]`：详情 + 价格反应 + Signal 关联。
- `GET /api/eqn-news/stream`：SSE，推新新闻、价格反应更新、worker 状态。模式参考 `/api/market-alerts/stream`。
- `GET /api/eqn-news/coin/[symbol]`：该币最近新闻时间轴，给 K 线标记用。
- 权限与现有页面保持一致，需要登录。

### 6.4 推送

- 复用现有 Web Push 订阅和 VAPID，不新建密钥。
- 默认规则：规则分 >=80 且有币安交易对的新闻推送；同一币种 10 分钟内只推一次。
- 设置页增加「新闻交易提醒」开关和分数门槛，默认关闭，用户手动打开。

## 7. 实盘交易

### 7.1 账户准备（用户操作，密钥不经过聊天和 Git）

币安：

- 新建子账户，只转入准备交易的小额 USDT 到子账户 U 本位合约钱包。
- 在子账户创建 API Key：只勾选「允许读取」和「允许合约」；不勾选提现、万向划转、杠杆、现货。
- IP 白名单只填 VPS 公网 IP。
- 合约设为单向持仓模式。

Hyperliquid：

- 在 HL 网页的 API 页面创建 API 钱包（agent wallet）并授权主账户。API 钱包只能下单撤单，不能提现和转账。
- 记录主账户地址和 API 钱包私钥；有效期按 HL 页面设置，到期前 7 天由 Signal 在状态栏和 Web Push 提醒续期。
- 主账户只放小额 USDC。

密钥存放：

- 用户自己登录 VPS，写入交易服务专用的环境文件，权限 600，只给 trader 服务的 systemd `EnvironmentFile` 读取。
- 变量：`BINANCE_TRADE_API_KEY`、`BINANCE_TRADE_API_SECRET`、`HL_ACCOUNT_ADDRESS`、`HL_AGENT_PRIVATE_KEY`。
- 网站进程、日志、数据库、前端都拿不到密钥；`.env.example` 只放变量名。

### 7.2 交易服务

- 新 systemd 服务 `signal-hub-trader`，只监听 `127.0.0.1`，Next.js 调用时带内部令牌（`TRADER_INTERNAL_TOKEN`）。web 进程不持有交易所密钥。
- 币安 U 本位合约：签名 REST 下单（`/fapi/v1/order`）、设置杠杆和逐仓、用 `exchangeInfo` 处理 `stepSize`、`tickSize`、`minNotional`；用 User Data Stream 接收成交和持仓更新；启动时同步服务器时间，`recvWindow=5000`。
- Hyperliquid：用官方 `hyperliquid-python-sdk` 签名，不手写签名逻辑；市价单按 HL 惯例用带滑点保护的 IOC 限价单；按 `szDecimals` 处理数量精度；用 WebSocket 订阅成交和持仓。
- 每个订单生成唯一客户端订单号（币安 `newClientOrderId`，HL `cloid`），网络超时后先按订单号查询再决定是否重发，避免重复下单。
- 止损止盈：开仓成交后立即挂 reduceOnly 的止损/止盈单；挂单失败时在页面红字提示并写日志，不自动平仓。
- 每 10 秒和每次成交后同步一次持仓、挂单、可用保证金，通过 `/api/trade/stream` SSE 推给页面。
- 服务开关：`TRADING_ENABLED`（默认 false）；`TRADING_MODE=readonly|live`，先用 readonly 只同步持仓不下单。

### 7.3 服务端风控（默认值待用户确认，配置在 VPS 环境变量）

| 规则 | 默认值 |
| --- | --- |
| 单笔名义价值上限 | 500 USDT |
| 单币持仓名义价值上限 | 1,000 USDT |
| 两个账户总持仓上限 | 3,000 USDT |
| 最大杠杆 | 5x |
| 当日亏损上限（已实现 + 未实现，北京时间 0 点重置） | 200 USDT，触发后只允许平仓 |
| 同币同方向重复下单间隔 | 10 秒 |
| 全局下单频率 | 每分钟 10 单 |
| 市价滑点保护 | 1%（币安用 IOC 限价单实现，HL 原生） |
| 快捷单的新闻时效 | 新闻发布超过 10 分钟后快捷按钮改为二次确认 |

风控在 trader 服务里执行，前端展示只是提示。平仓、撤单、全部平仓不受开仓限制约束。

### 7.4 访问控制

- `/api/trade/*` 需要网站登录，且只接受同源 POST（校验 Origin），带 CSRF 令牌。
- 交易解锁：首次下单前输入交易 PIN（与网站登录密码分开，哈希存 VPS），解锁有效 8 小时，可在页面手动锁定。
- `/news` 及相关接口沿用网站登录授权。交易写入另需 PIN 解锁。

### 7.5 下单记录

- 表 `trade_orders`：客户端订单号、关联新闻 `no`、账户、交易对、方向、名义价值、杠杆、类型、风控结果、交易所订单号、状态、成交均价、数量、手续费、请求耗时、错误码、创建时间。
- 表 `trade_fills`：成交明细，用于 K 线 B/S 标记和后续复盘（新闻类型 vs 收益）。
- 日志和数据库不记录密钥、签名、私钥。

### 7.6 交易上线顺序

1. 币安合约测试网和 HL 测试网跑通开仓、止损止盈、平仓、全部平仓。
2. 生产 `TRADING_MODE=readonly` 跑 1 天，核对持仓和余额与交易所 App 一致。
3. 切到 live，风控单笔上限临时设为 20 USDT，用户本人各下一笔真单验证，再恢复默认值。

## 8. 分期

1. 第一期 新闻 MVP：worker 入库（WS + main 补漏 + 其他频道轮询）、`/news` 页面新闻流、频道/搜索/来源筛选、状态栏、手机列表。
2. 第二期 行情联动：K 线区、新闻标记、价格反应计算、币种详情标签、Signal 关联、`/api/v1` 字段增强。
3. 第三期 实盘交易：trader 服务、两个交易所接入、交易面板、快捷单、持仓挂单区、风控、交易解锁、全部平仓，按 7.6 节顺序上线。
4. 第四期 提醒与复盘：Web Push 规则、多流分屏、按新闻类型统计价格反应和自己的交易盈亏。

每期单独提交、推送、部署，前一期在线上跑稳 2 天后再开始下一期。第三期的交易面板依赖第二期的 K 线区和币种映射。

## 9. 验收标准

- 新闻从 eqn WS 收到到页面显示，中位延迟 <=3 秒（worker 日志记录 `received_ts - published_ts`）。
- worker 重启或 WS 断开 5 分钟后恢复，断线期间 main 频道新闻零遗漏（与 `list_news` 对比）。
- 同一 `no` 不重复显示；转载新闻按规则合并显示。
- 24 小时运行无 429 封禁暂停超过 1 次。
- `/api/v1` 全部失败时，新闻流、K 线和价格反应仍可用，只缺发布时市值和公告要点。
- 桌面 1280/1440/1920 和手机 390 宽度下无文字溢出、无重叠，K 线非空白。
- 关闭 `EQN_NEWS_ENABLED` 后 worker 停止请求 eqn，页面显示「数据源未启用」。
- 交易：测试网上币安和 HL 各完成开多、开空、止损触发、手动平仓、全部平仓；网络超时重试不产生重复订单。
- 风控：每条规则都能在测试网拦截；当日亏损触发后只能平仓。
- 安全：web 进程环境变量和接口响应里查不到交易密钥；未登录或未解锁调用 `/api/trade/*` 返回 401/403；trader 端口外网不可访问。
- 持仓同步：页面持仓、余额与交易所 App 一致，延迟不超过 10 秒。
- 不影响现有服务：web、monitor985、x-owned-reader、web-push 均保持 active，`/login` 返回 200。

## 10. 给 Codex 的测试清单

- WS 帧解析：秒级时间戳转毫秒、`coins_included` 为空、超长标题。
- 心跳与重连：30 秒 ping、1008/1012/1013 关闭码的退避行为。
- 补漏：断线前后游标衔接、`next_cursor` 翻页终止条件。
- 去重合并：WS 占位记录与 MCP 详情合并、重复报道识别。
- 限流：429 + Retry-After 全局暂停、预算计数器。
- `/api/v1` 解析：字段缺失、结构变化时降级不抛错；`/api/v1/market` 的 `k` + `rows` 解码。
- 规则评分：每条规则一个用例，边界分数 70 / 80。
- 价格反应：无交易对、K 线缺失、时间未到。
- 币种映射：`asset_id`/symbol 到币安交易对，含 1000 倍币（例如 1000PEPE）。
- 接口：筛选参数校验、limit 上限、未登录 401。
- 交易精度：币安 `stepSize`/`tickSize`/`minNotional`，HL `szDecimals` 和价格有效位数。
- 交易对映射：币安与 HL 的 1000 倍币、`k` 前缀币，以及只在其中一个交易所上线的币。
- 风控：每条规则一个用例，含边界值；平仓不受开仓限制。
- 幂等：下单超时后按客户端订单号查询，确认不重发。
- 止损止盈：开仓成交后挂单成功和挂单失败两种路径。
- 访问控制：未登录、未解锁、跨站请求、内部令牌错误。
- 密钥泄漏：日志、数据库、API 响应、前端产物扫描不到密钥变量值。
- 交易所错误映射：币安常见错误码（余额不足、精度错误、超时、IP 不在白名单）和 HL 拒单原因转成中文提示。
- 页面：Playwright 截图桌面和手机，新消息浮条、选中新闻联动 K 线、空状态、断线状态。

## 11. 风险

- `eqn.news/api/v1` 不在公开文档里，字段和地址可能随时变化，只能作为增强层。
- 新闻是自动抓取和机器翻译，可能有误译或延迟；页面底部固定显示「数据来自方程式新闻，不构成投资建议」。
- WS 只覆盖 main 频道，其他频道靠 15 秒轮询，最多慢 15 秒。
- 所有请求来自同一 VPS IP，与其他服务无共享额度，但如果后续再接 eqn 的其他功能，要共用第 4.2 节的预算。
- 规则评分简单，前期可能误标重要性；第四期用实际价格反应统计后再调整。
- 实盘风险：新闻交易靠速度，机器翻译误读、重复报道、假消息都可能导致亏损；快捷单默认二次确认，风控只能限制亏损规模，不能判断对错。
- 网站账户被盗即等于交易账户可被操作，因此加交易 PIN、只放小额资金、API 不开提现。
- 币安 API 依赖 VPS IP 白名单，VPS 换 IP 后需重新设置；HL API 钱包有有效期，到期后下单失败。
- 下单从浏览器到交易所要经过 VPS（首尔），延迟预计 100-300ms，比交易所 App 慢。
- 新服务增加 VPS 负载：预计常驻内存 <100MB，SQLite 30 天约几十 MB，需在部署后检查。
