# EquationNews Backend

## Public Contract

Shared browser types in `news-terminal-types.ts` are unchanged. All routes are private through the existing `src/proxy.ts`; there are no upstream credentials or new public auth exceptions.

- `GET /api/eqn-news?channel=&coin=&q=&source=&before=&limit=` returns `NewsFeed`. `channel=all`, limit 100 by default, capped at 200. Search and source filters apply to the local retained corpus, not a promise of complete upstream history. `before` is an opaque local keyset cursor; do not pass an MCP cursor here.
- `GET /api/eqn-news/coin/[symbol]` returns the same paginated `NewsFeed` filtered to that coin.
- `GET /api/eqn-news/channels` returns `{ channels: string[] }`.
- `GET /api/eqn-news/[id]?coin=&venue=` returns `NewsDetail`. Optional coin must be a valid ticker, venue must be `binance` or `hyperliquid` (default Binance). Reactions use only the requested coin if it belongs to this news item, on that venue, with no silent cross-venue fallback. Valid but unassociated tickers return all-null reactions, empty related news and empty signals, without another asset's data. Related news/signals are scoped to the selected coin; omitting coin preserves the existing multi-coin related content and first-coin reaction default. Re-fetching detail every 30 seconds updates pending windows. IDs are decimal official news numbers or `ws:<sha256>` temporary IDs. Old temporary IDs remain aliases after canonical merge until retention removes the record. Next route params are already URL-decoded.
- `GET /api/eqn-news/stream` sends `event: message` with `{type:"update",status:NewsWorkerStatus}` on database revision changes and periodic status refresh. Re-fetch the feed. Existing SSE helper provides heartbeat, abort cleanup and slow-reader disconnection. Reactions are computed on detail reads, not pushed as independent persisted records.
- `GET /api/eqn-news/market?symbol=BTC&interval=1m&venue=binance` returns `NewsMarket`. Venues: `binance`, `hyperliquid`; intervals: `1m,5m,15m,1h,4h,1d`. Optional `assetId` is a fail-closed identity constraint. A market response may contain partial data and a non-null `error`. `pair=null` means no current verified mapping, never inferred trading availability. Unknown venues/intervals return 400; storage failures return 503; missing detail returns 404. Errors are `{error:string}`.

`NewsItem.publishedAt`, `receivedAt`, `NewsMarket.fetchedAt`, worker timestamps, all internal exchange candles and reaction inputs use UTC **milliseconds**. Only public `NewsMarket.candles[].time` uses Unix **seconds** for chart compatibility. Prices/candle OHLC and base volume are **native instrument values**, including 1000PEPE and kPEPE: never divide by 1000 before passing a limit price to the trader. `symbol` remains the requested news ticker (PEPE); `pair` names the actual instrument (1000PEPEUSDT / kPEPE). Ticker volume and OI are USD quote notional; OI = native quantity * native instrument price, exactly once. Funding is the venue's fractional period rate, not annualized.

## Enablement And Storage

Requires Node >=22.5 with built-in WebSocket and node:sqlite (repository runtime uses Node 24). No package changes or API keys required. Scripts do not load `.env`, `.env.local`, trading credentials, or session files.

Run with `node --experimental-strip-types --experimental-transform-types scripts/eqn-news-worker.mjs --doctor` or `--once`. Default `EQN_NEWS_ENABLED=false` means zero upstream requests. Set `EQN_NEWS_ENABLED=true` in the worker and web process to enable ingestion/status. `--doctor` is a bounded official read/detail/storage probe, not an assertion that historical catch-up is finished. `--once` performs one bounded pass; repeat or run continuously to complete backlog.

`EQN_NEWS_DB` overrides the database path. Otherwise use `SIGNAL_HUB_RUNTIME_DIR/eqn-news/news.sqlite` through `runtime-storage.ts`. Keep worker and web runtime roots identical. WAL and busy timeout permit separate processes. Retention is 30 days, with a 100,000-record safety cap at daily pruning; aliases and orphan detail retry state are also removed. Never clear the shared runtime root.

The independent `deploy/systemd/signal-hub-eqn-news.service` follows the existing Ubuntu user and `/home/ubuntu/signal-hub` working directory. It defaults disabled. The optional `/etc/signal-hub/eqn-news.env` can set only news/storage options, including `EQN_NEWS_ENABLED=true`. Create the shared `.signal-hub` directory before starting the hardened unit. No other service units, production configuration, commits or deployments are changed by this implementation.

Optional `EQN_NEWS_RSS_FALLBACK=true` enables ETag RSS fallback, at most once per channel per minute. RSS does not advance MCP watermarks. Optional `EQN_NEWS_V1_AUGMENT=true` enables undocumented v1 augmentation: only enrich existing official IDs' coin metadata/digest, never replace core text, inject coins or create records. Five failures pause it for ten minutes. Both options default off; official MCP alone provides usable core news, details and coin associations.

## Correct Gap Filling And Limits

Verified publicly on 2026-11-16 using https://eqn.news/api-docs and live credential-free MCP requests. MCP uses Streamable HTTP JSON-RPC `initialize`, `notifications/initialized`, then `tools/call`. Session/protocol headers are supported. Real `list_news` fields are `no,time,channels,source,zh,en,coins:string[],url,source_url`, not a required `i18n` object. Real `get_news` adds `body,images,telegram,data`. `structuredContent` and JSON text content are both supported, as are bounded SSE responses.

Live evidence: main page yielded IDs 15258 and 14273 with `next_cursor=1794545203692-14273`; requesting that **before** cursor yielded older ID 14236 at `2026-11-13T02:25:02.492Z`. Detail 15258 supplied English/Chinese text, LIT, and a relative image path correctly normalized to an HTTPS URL. These are observations, not permanent fixtures or latest-news promises.

`before` means **older**, never "after the last received item". Each fresh scan starts at the newest page and walks backward to the previously persisted channel watermark. A bounded interrupted scan persists its current older-page cursor and original boundary; it resumes without advancing the watermark until complete. New arrivals during this scan are collected on the next fresh scan (or WS for main). Invalid records and repeated cursors hold the watermark and surface an error. Different official `no` values are not collapsed merely because titles look alike. WS placeholders merge by source URL and second timestamp, or an exact bilingual text/source match within the same second if both lack a source URL.

No absolute <=3 second latency or zero-loss guarantee is possible: WS has no replay, API history is bounded, channels differ, workers may be offline or rate limited, and source publication can be delayed. The collector targets a 15-second polling cadence, but bounded sequential budgets, retries and backlog can extend it. Reconnect schedules the next main polling scan, not an invalid older-cursor "replay". Status shows incomplete channel backfill and heartbeat staleness (>90 seconds). API consumers should display `error` even while `connected=true` or persisted items are available.

Public WS is one main-feed connection, sends plain `ping` every 30 seconds, requires `pong` within 65 seconds, caps handshake at 10 seconds, reconnects with jittered exponential 1..30 second backoff, and uses at least 30 seconds for policy/overload closes. A polling path remains active during disconnection. There is no subscription JSON or replay command.

One client serializes **all** news HTTP requests with >=500ms spacing (<=20 requests/10 seconds). HTTP 429 persists a global cooldown and retries at most twice. Respect Retry-After seconds/date (default 15 seconds); cooldowns >30 seconds fail the current operation promptly and resume in later passes. HTTP headers plus body have a 10-second timeout, 4MB response cap, and abort support. Run only one worker per runtime/database; the budget is per worker instance, not a multi-worker distributed lease.

Market cache: 128 LRU entries, 24 in-flight keys, 15-second market/ticker/candle TTL, five-minute Binance metadata TTL and 15-second HL metadata/context TTL. Exchange requests have 8-second header/body timeouts and bounded candle windows (<=1440 bars; typical 500). Shared Binance request reservations and persisted 429 cooldowns reuse `market_alert_binance_rate_limit` in `MARKET_ALERTS_DB` if present. No new alerts database is created just for news.

Existing `market-alerts-store.ts` uses `MARKET_ALERTS_DB` or `market-alerts/alerts.sqlite` for valuations, volatility alerts and shared Binance rate limiting. The independent `market-signals.ts` uses `MARKET_SIGNALS_DB` or `market-alerts/signals.sqlite` for strategy signals. Related event lookup reads both, read-only. Valuations older than 24 hours or missing are null, never fabricated from price/supply. Runtime database path settings must match the existing workers.

## Mapping And Reactions

Unknown new-listing symbols are supported through one exact active `baseAsset`/`USDT`/`PERPETUAL` Binance metadata entry or one exact non-delisted HL `name`. No fuzzy substrings, blind USDT stripping, or arbitrary numeric/k-prefix removal. Only explicit alias registry entries (e.g. PEPE -> 1000PEPE / kPEPE) allow scaled mapping. Supplied unknown/conflicting asset IDs fail closed. This is market display metadata, NOT order authorization: trader must independently validate identity, listing status, precision and risk at order time.

US-equity and other TradFi news symbols fall back to chart-only markets: Binance `TRADIFI_PERPETUAL` (for example `NVDAUSDT`) and the Hyperliquid HIP-3 `xyz` dex (for example `xyz:NVDA`). Crypto perpetuals always win when both exist. These responses carry `tradable:false`; the UI disables opening orders because the trader only supports standard crypto perpetuals.

When EquationNews sends no coins, only explicit quote-suffixed pairs in the title/original are extracted (`LONGXIAUSDT`, `[龙虾USDT]`; at most 5, Han runs at most 6 characters). Symbols may contain Han characters because Binance lists CJK-named perpetuals; those are chart-only since the trader accepts ASCII symbols. Rows stored earlier are repaired once (`migration:textCoins:v1`).

Chart latency: Binance klines and exchange metadata are interactive and may skip at most 1s of the shared market-alert limiter backlog (they still advance its slot and honor 429/418 blocks). Ticker, funding and OI wait at most 1.2s; late values warm the cache. Price falls back to the live candle close, 24h stats to a fresh (<3 min) market-alert ticker snapshot. Exchange metadata is served stale while refreshing. The browser keeps the last 8 successful charts in `localStorage` and shows them immediately with trading disabled until the refresh lands.

The terminal requests `view=chart` first (metadata + candles only), then `view=stats` for display metrics. Omitting `view` preserves the full response. Recent candle histories are retained for at most 64 venue/pair/interval combinations, up to 500 bars each; refreshes overlap the last mutable candle and fill intervening bars. Explicit historical/reaction ranges have separate cache keys. Browser requests are deduplicated by symbol, venue, interval and asset identity. Hover/focus can preload charts; mobile observes visible coin buttons (at most two per observation pass). Speculative requests have one concurrent request, a two-entry queue, a 30s per-selection cooldown and a total budget of six per minute.

The selected chart subscribes directly to Binance `wss://fstream.binance.com/market/ws/<pair>@kline_<interval>` or Hyperliquid's candle subscription. Only verified metadata pairs are subscribed. Candle times use seconds in the browser, native instrument OHLC values are retained, and mismatched/out-of-order messages are rejected. Reconnect and missing intervals trigger REST gap filling. While receiving live candles, 30s chart polling is skipped; statistics refresh every 60s. If live data stalls for 45s, the socket reconnects with bounded exponential backoff and REST polling continues. Hidden tabs release the socket; return-to-foreground refreshes history. Cached/failed charts retain an error marker that disables opening orders until an HTTP chart refresh succeeds. Live candle updates use the chart's incremental update API.

Background limiter reservations wait outside the local dispatch queue. Dispatch still spaces actual requests by 200ms and checks venue cooldowns. The separate `view=stats` request uses interactive limiter reservations and awaits its own metrics so a cold funding/OI cache can fill on the first response. Only the legacy full response retains the 1.2s optional-metric deadline.

Source blocking: `GET/PUT /api/eqn-news/sources` (login; PUT also same-origin). Blocked source keys (case-insensitive) are stored in SQLite state `blockedSources`, are skipped at ingestion by the worker, and existing rows are hidden from the feed until unblocked.

Reactions are **1m candle-open approximations**, not an observed publication trade/tick price and not candle high/low/close lookahead. Baseline is the first candle open at/after publication within one minute. Each target uses the first open at/after publication+window within one minute, not an older candle. Future targets, missing bars and unmapped assets remain `change:null`. A non-minute-aligned publication may require waiting for the next minute boundary even after the nominal window has elapsed. No "price before publication" or exact execution-price claim is made. Detail reactions use the explicitly selected Binance or Hyperliquid venue (Binance by default), never an implicit fallback. Related signals include existing persisted market/strategy events and exact-uppercase coin-token matches in the last 24h of persisted X/TG feed snapshots (at most 8MB/5000 items per snapshot). This is text association, not proof that posts describe the same event; ambiguous lowercase tickers are not matched. Snapshot paths follow the existing X/TG cache functions and their explicit path overrides.
